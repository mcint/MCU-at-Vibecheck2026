all plots ↗ What you're looking at. A tiny game: three numbers; each turn you click one — it doubles, the other two lose 1. In abc values floor at 0 (and 0·2=0, so a zero is forever); in abc-1 there is no floor and negatives double downward. What's proven (Lean 4, kernel-checked): start (2,2,2) is dead in 2 moves for every play; (3,3,3) can live forever but min never exceeds 3 for any play of any length; (4,4,4) grows without bound. For the product objective, balance is exactly optimal in abc, but in abc-1 pressing one key forever is optimal for every horizon N — the sign trick. How to attack it: play the bars (keys a b c, u undo) and try to beat each bound. The theorem statements shown are copied verbatim from the .lean files; the JS only re-implements step for interactivity — the proofs are about Abc.lean, not this page.

Rules (the whole game)

  1. Three integers a b c. One move per turn: pick one.
  2. The picked value doubles; the other two drop by 1.
  3. abc: values floor at 0 (and 0·2 = 0, so a zero is forever).
    abc-1: no floor; a negative doubles downward.
  4. Score after N turns: min (keep the weakest alive) or product a·b·c.

The one step both variants share verbatim from Abc.lean

Abc.leaninductive Variant | sat | nosat

/-- saturation: `abc` clamps at 0, `abc-1` doesn't. -/
def clamp : Variant → Int → Int
  | .sat,   x => max 0 x
  | .nosat, x => x

def step (v : Variant) (s : St) : Act → St
  | .A => ⟨clamp v (2 * s.a), clamp v (s.b - 1), clamp v (s.c - 1)⟩
  | .B => ⟨clamp v (s.a - 1), clamp v (2 * s.b), clamp v (s.c - 1)⟩
  | .C => ⟨clamp v (s.a - 1), clamp v (s.b - 1), clamp v (2 * s.c)⟩

def score (s : St) : Int := min s.a (min s.b s.c)

/-- If all three values are ≥ 1 before a move, saturation never triggers: both variants agree. -/
theorem step_agree (s : St) (h : alive s = true) (act : Act) : step .sat s act = step .nosat s act
'Abc.step_agree' depends on axioms: [propext, Classical.choice, Quot.sound]

Abc.lean/-- x² = (x+c)(x−c) + c²: spreading two equal factors apart loses c². -/
theorem spread_loses (x c : Int) : (x + c) * (x - c) + c * c = x * x := by grind
/-- Three in a row lose to three equal: (x−1)·x·(x+1) = x³ − x < x³ for x ≥ 1. -/
theorem cube_balance (x : Int) (h : 1 ≤ x) : (x - 1) * x * (x + 1) < x * x * x := by grind

Perturbations. What survives when the problem is tweaked? Monotone rescoring: same answer (one line). Even dimension: spam fails — one negative means product ≤ 0. The 3D theorem rests on sign parity.

Reading: with an odd number of coordinates, spam leaves an even number of negatives and the untouched negatives are free magnitude. Even dimension forces a dip, the box invariant stops being tight (box_loose_2d: 128 ≪ 2304), and a proof would need an order argument. The smaller problem is the harder theorem.
